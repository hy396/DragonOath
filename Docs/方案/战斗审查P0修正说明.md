## 当前实现边界

### 伤害、治疗与死亡

- `UDOHealthSet` 只负责 Meta Attribute 到最终 Health 的数值转换、数值事件与 `OnOutOfHealth` 幂等入口。
- `UDOHealthComponent` 负责蓝图委托、死亡状态机、死亡 Tag、权威端本机 `FDOVerbMessage` 广播。详见 [DOHealthComponent.h（职责边界）](../../Source/DragonOath/Components/DOHealthComponent.h)。
- 吸血只在服务器权威结算，计算公式为最终实际伤害 × `LifeStealRate`；客户端不能额外结算最终 Health。
- `Message.Combat.DamageApplied` 只代表真实 Damage Meta 的最终扣血，**不代表**治疗、自然回复或上限 clamp。

### Dash / Dodge

- 当前 C++ Dash 技能已经用 `ActivationOwnedTags` 管理 `Status.Dashing`，并用 `ActivationBlockedTags` 阻止重入，见 [DOGameplayAbility_Dash.cpp](../../Source/DragonOath/AbilitySystem/Abilities/Common/DOGameplayAbility_Dash.cpp)。
- 编辑器资产仍须按 [闪避改造_蓝图待办.md](../蓝图需要做的事情/闪避改造_蓝图待办.md) 配置 Repeated Tap、InputTag 与 AbilitySet；不要恢复角色层手写双击逻辑。
- DashAttack 窗口是 Dash 结束后短暂存在的 GE，因此不能用 `ActivationOwnedTags` 或 Loose Tag 代替。

### 跨网战斗消息：仍未接线

[FDOVerbMessageReplication](../../Source/DragonOath/Messages/DOVerbMessageReplication.h) 容器及客户端 rebroadcast 代码存在，但当前没有复制宿主、`UPROPERTY(Replicated)`、`DOREPLIFETIME` 或生产发布点。因此：

- 当前伤害/击杀 Verb Message 仅在**服务器本机** `GameplayMessageSubsystem` 广播；
- 不得将其描述为远端客户端伤害飘字已完成；
- 在决定消息宿主、受众/相关性、可靠性、TTL、去重和晚加入语义前，不接入 FastArray。

相关规范见 [本地消息总线文档](../04_Local_Message_Bus.md) 与 [技术架构](../02_Technical_Architecture.md)。
