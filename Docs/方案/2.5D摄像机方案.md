# 07. 2.5D Camera Design

## 1. 方案结论

DragonOath 采用“固定侧视为主、轻微软跟随、允许有限纵深”的 2.5D 摄像机方案。

推荐组合：

```text
透视投影
  -> 固定侧视方向
  -> 摄像机不接受玩家自由旋转输入
  -> 摄像机只在水平轴和垂直轴上跟随
  -> 纵深轴不跟随，避免画面左右摆动
  -> 由关卡边界限制可视区域
  -> 技能、受击和大招通过本地镜头反馈短暂改变表现
```

这样既保留 3D 角色、骨骼动画、Niagara 特效和纵深遮挡，又不会退化成自由视角 3D 动作游戏。

第一阶段不建议使用完全自由的第三人称摄像机，也不建议一开始使用完全正交投影。正交投影虽然容易做出纯横版效果，但空间层次、特效纵深和角色远近关系会比较僵硬；自由第三人称镜头则会破坏横版操作的方向感和技能可读性。

## 2. 世界坐标约定

项目按以下方式组织 2.5D 游戏空间：

```text
X  横向战斗轴：角色向左/向右移动，普攻和大多数弹道沿此轴释放
Y  纵深轴：角色在前后小范围走位，用于躲避和站位
Z  垂直轴：跳跃、浮空、击飞和落地
```

摄像机从 Y 轴负方向观察场景，朝 Y 轴正方向看入关卡：

```text
摄像机位置：远离角色的 Y-
摄像机朝向：固定看向 Y+
屏幕横向：对应世界 X 轴
屏幕纵向：对应世界 Z 轴
```

角色的朝向保持在 X 轴正向或负向。摄像机不参与角色转身，角色也不跟随摄像机旋转。这与当前 `ADOPlayerCharacter` 中关闭 `bUseControllerRotationYaw` 和 `bOrientRotationToMovement` 的做法一致。

> 实现时应以“X/Z 是屏幕平面、Y 是纵深”为唯一约定。输入注释、碰撞体、技能范围和关卡摆放都要遵守同一套坐标定义。

移动速度、纵深轴输入、纵深边界和蓝图调参方案单独维护在[2.5D纵深移动方案](2.5D纵深移动方案.md)中。

## 3. 摄像机形态

### 3.1 投影方式

使用透视摄像机，但把透视感控制在较弱范围内。

建议的 P0 起始参数：

| 参数 | 建议值 | 说明 |
|---|---:|---|
| Projection | Perspective | 保留 3D 场景和特效的空间感 |
| FOV | 28°～35° | 先从 32° 开始，避免远近缩放过强 |
| 侧视偏移 | Y 轴固定 | 不随角色前后走位改变视角方向 |
| 俯角 | 8°～12° | 只露出少量地面，辅助判断纵深 |
| 镜头滚转 | 0° | 不让画面产生横版游戏不需要的倾斜 |
| Camera Lag | 关闭或很低 | 保证战斗输入和画面反馈直接 |
| Camera Collision | P0 关闭 | 避免镜头靠近墙体时突然缩放或抖动 |

摄像机不应通过 Spring Arm 的碰撞检测自动缩短距离。横版关卡的镜头位置应该由关卡设计和边界体控制；如果镜头遇到遮挡，应优先处理场景层级、透明淡出或镜头区域切换，而不是让镜头突然贴到角色脸上。

### 3.2 镜头目标点

镜头跟随的不是角色胶囊体中心，而是一个可配置的目标点：

```text
TargetPoint = 角色位置
            + X 轴前视偏移
            + Z 轴构图偏移
            + 受击/技能等临时本地偏移
```

建议起始值：

- X 轴前视偏移：角色朝向前方 100～220 cm。
- Z 轴构图偏移：角色胶囊中心上方 80～140 cm。
- 跳跃时不立即把镜头拉到最高点，使用较慢的垂直跟随速度。
- 落地后使用较快的垂直回归，避免镜头长时间漂浮在空中。

前视偏移可以让玩家看到角色前方的敌人和弹道，但不能随着角色左右转身瞬间跳动。左右翻面时应通过插值平滑过渡，避免画面突然向另一侧移动。

### 3.3 跟随规则

采用“死区 + 软跟随”的方式：

```text
角色在屏幕中心附近移动
  -> 摄像机基本不动

角色接近屏幕左/右安全边界
  -> 摄像机开始沿 X 轴跟随

角色跳跃或被击飞
  -> 摄像机沿 Z 轴低强度跟随

角色沿 Y 轴前后移动
  -> 摄像机不跟随，只保持固定侧视方向
```

建议起始参数：

| 参数 | 建议值 |
|---|---:|
| X 轴死区 | 屏幕宽度的 20%～30% |
| Z 轴死区 | 屏幕高度的 15%～25% |
| X 轴跟随速度 | 8～12 |
| Z 轴跟随速度 | 上升 4～7，下降 8～12 |
| 关卡边界缓冲 | 100～250 cm |

具体数值必须通过测试关卡调手感，不能把这些数值当成最终美术标准。

### 3.4 手动镜头平移

在自动跟随之外，允许玩家使用方向键主动移动镜头。这里的“上下左右”是移动镜头目标点，不是旋转摄像机：

```text
← / →  沿世界 X 轴移动镜头
↑ / ↓  沿世界 Z 轴移动镜头
Y      保持固定
Yaw    保持固定
Pitch  保持固定
Roll   保持为 0
```

推荐行为：

```text
没有方向键输入
  -> 摄像机按自动跟随规则工作

按住方向键
  -> 增加本地 ManualOffset
  -> 摄像机向对应方向平移

松开方向键
  -> 保留当前手动偏移，不立即自动归中

按下摄像机复位键
  -> 清空 ManualOffset
  -> 摄像机平滑回到玩家构图中心
```

建议的 P0 参数：

| 参数 | 建议值 | 说明 |
|---|---:|---|
| `PanSpeed` | 600 cm/s | 方向键持续按住时的平移速度 |
| `PanLimitX` | 500 cm | 手动镜头横向最大偏移 |
| `PanLimitZ` | 250 cm | 手动镜头垂直最大偏移 |
| `ResetBlendTime` | 0.2 s | 复位时的平滑时间 |
| `ResetSpeed` | 10～15 | 复位插值速度 |

手动偏移不应直接改变摄像机世界坐标，而应叠加到自动跟随目标上：

```text
AutoTarget   = 根据玩家位置和死区计算的自动跟随目标
ManualOffset = 方向键累积出的本地镜头偏移
DesiredTarget = AutoTarget + ManualOffset
```

伪代码：

```cpp
ManualOffset += CameraPanInput * PanSpeed * DeltaSeconds;

ManualOffset.X = FMath::Clamp(ManualOffset.X, -PanLimitX, PanLimitX);
ManualOffset.Z = FMath::Clamp(ManualOffset.Z, -PanLimitZ, PanLimitZ);
ManualOffset.Y = 0.0f;

DesiredTarget = AutoTarget + ManualOffset;
DesiredTarget = ClampToCameraBounds(DesiredTarget);
CurrentTarget = SmoothInterpolate(CurrentTarget, DesiredTarget);
```

### 3.5 玩家安全区

手动移动镜头不能让玩家完全离开屏幕。镜头需要额外定义“玩家安全区”：

```text
玩家在安全区内
  -> 允许继续手动移动镜头

玩家接近屏幕边缘
  -> 限制继续向该方向平移
  -> 或逐渐减少对应方向的 ManualOffset

玩家即将离开屏幕
  -> 自动跟随优先级高于手动偏移
  -> 强制镜头把玩家拉回安全区
```

推荐安全区占屏幕范围：

```text
横向：屏幕宽度的 25%～75%
纵向：屏幕高度的 20%～80%
```

实现上可以先计算不带手动偏移的 `AutoTarget`，再检查玩家在 `DesiredTarget` 下的屏幕位置。如果玩家超出安全区，则减少对应方向的 `ManualOffset`，而不是让玩家消失后再瞬间把镜头拉回来。

安全区规则优先级高于手动镜头偏移，但低于关卡边界。最终优先级为：

```text
关卡边界 > 玩家安全区 > 自动跟随死区 > 手动镜头偏移
```

### 3.6 镜头复位

增加独立的 `IA_CameraReset` 输入。按下后清理手动偏移：

```cpp
void ResetCamera()
{
    ManualOffset = FVector::ZeroVector;
    bCameraResetting = true;
}
```

默认采用 0.15～0.25 秒平滑回归：

```cpp
CurrentTarget = FMath::VInterpTo(
    CurrentTarget,
    AutoTarget,
    DeltaSeconds,
    ResetSpeed);
```

复位期间仍然保留关卡边界和玩家安全区检查。复位完成后恢复正常的“自动跟随 + 手动偏移”模式。

推荐把复位键预留为 `Home`，但最终按键仍应由 `DA_InputConfig` 和 `IMC_Default` 配置，不在 C++ 中硬编码具体物理键。

## 4. 纵深设计

2.5D 不等于让角色在整个 3D 世界里自由移动。第一阶段应把纵深控制在战斗可读的范围内。

### 4.1 推荐：战斗纵深通道

每个战斗区域配置一个纵深通道：

```text
区域纵深范围：Y = [DepthMin, DepthMax]
角色可以在范围内前后走位
超出范围时由碰撞体或移动组件限制
摄像机不随 Y 轴移动
```

推荐起始宽度为 300～600 cm，具体由角色体型、近战攻击范围和怪物数量决定。近战区可以窄一些，Boss 区和多人战斗区可以宽一些。

不要在第一版开放无限纵深，原因是：

- 玩家容易走到屏幕前后方而看不清自己。
- 近战命中和弹道的空间关系变复杂。
- 怪物可能在视觉上重叠，导致目标选择困难。
- 摄像机不跟随 Y 轴时，远近距离只能靠特效和阴影表达。

### 4.2 纵深表现规则

- 角色可以通过轻微缩放、阴影和遮挡关系表现远近，但不要使用明显的动态缩放。
- 角色名字、血条和伤害数字使用世界空间组件时，需要设置合理的屏幕尺寸，避免远近变化过大。
- 远近角色的排序由真实深度和渲染规则决定，不要只依赖 Sprite 式的手动排序。
- 近战命中应同时检查 X、Y、Z 三轴范围；不能因为屏幕上重叠就直接判定命中。
- 远程弹道默认沿角色朝向的 X 轴移动，Y 轴误差需要由技能类型明确配置。

## 5. 关卡镜头边界

### 5.1 边界体

每个地图或战斗房间配置一个 2.5D 摄像机边界体，用来限制镜头目标点，而不是限制角色本身。

边界体至少包含：

```text
MinX / MaxX       镜头目标点的横向范围
MinZ / MaxZ       镜头目标点的垂直范围
DepthMin / Max    角色可活动的纵深范围，可选
CameraSettings    当前区域的镜头参数覆盖，可选
```

镜头计算流程：

```text
获取本地玩家镜头目标点
  -> 应用前视偏移和本地镜头反馈
  -> Clamp 到当前边界体
  -> 进行平滑插值
  -> 设置 PlayerCameraManager 的最终视点
```

如果一个地图有多个房间，不应把整张地图做成一个巨大边界体。推荐每个房间使用独立边界，并在角色进入新房间时进行 0.2～0.5 秒的镜头参数过渡。

### 5.2 关卡切换和门口

门、传送点和房间切换处可以使用以下方式：

1. 角色进入触发盒。
2. 激活下一个房间的镜头边界和镜头参数。
3. 镜头目标点在短时间内平滑过渡。
4. 角色和敌人仍由正常移动、碰撞和网络逻辑处理。

不要通过瞬间 Teleport 摄像机来切换房间，除非是加载新地图或明确的剧情镜头。

## 6. 技能和战斗镜头反馈

镜头反馈属于本地表现，不参与伤害结算，也不改变服务器权威状态。

推荐反馈层级：

| 反馈 | 表现 | 建议 |
|---|---|---|
| 普攻命中 | 轻微震动、极短 FOV 变化 | 低强度，不能影响瞄准 |
| 受击 | 局部镜头震动或短暂偏移 | 客户端本地播放 |
| 闪避 | 轻微拖尾感或短暂 FOV 变化 | 不要把镜头拉向位移终点 |
| 大招 | 短暂拉远、聚焦或后处理 | 需要可跳过，不能遮挡战斗信息 |
| Boss 阶段切换 | 轻微镜头过渡 | 只表现阶段变化，不锁死玩家输入 |

触发建议：

```text
服务器/GAS 产生权威战斗结果
  -> GameplayCue 或复制结果到达本地
  -> 本地 GameplayMessageRouter 通知 Camera / VFX / Audio
  -> 本地 PlayerCameraManager 播放反馈
```

不能由服务器直接设置所有客户端摄像机，也不能让摄像机反馈参与服务器命中判断。客户端预测的技能镜头可以先播放，技能被拒绝时由本地清理或回退表现。

## 7. 联机规则

摄像机属于 `LocalPlayer` 表现层，原则上不复制以下内容：

- 摄像机位置和旋转。
- 摄像机 FOV。
- 摄像机震动状态。
- 本地死区和跟随速度。
- 本地镜头后处理参数。

每个客户端只跟随自己的本地 `ADOPlayerCharacter`。Listen Server 和 Client 可以看到不同的镜头位置，这是正常现象，不影响角色、技能、伤害和死亡同步。

多人同屏的第一阶段建议仍然以“每个客户端跟随自己的角色”为准。不要为了让多个客户端看到同一构图而同步镜头。将来如果支持本地双人或共享屏幕，再单独设计“多个本地玩家包围盒取景”的模式。

## 8. UE 实现建议

### 8.1 推荐目录和职责

后续正式实现建议使用以下结构：

```text
Source/DragonOath/Camera/
  DOPlayerCameraManager.h/.cpp
  DO2DCameraBoundsVolume.h/.cpp
  DO2DCameraSettings.h/.cpp 或 DataAsset 对应类
```

职责划分：

- `ADOPlayerCameraManager`：计算本地最终镜头、死区、跟随、边界、镜头反馈和模式混合。
- `ADO2DCameraBoundsVolume`：提供当前区域的 X/Z 镜头边界和可选参数覆盖。
- `UDO2DCameraSettings` 或 `DA_Camera_2D_Default`：保存 FOV、跟随速度、死区、偏移、震动强度等数据。
- `ADOPlayerController`：指定 `PlayerCameraManagerClass`，不负责具体的镜头数学计算。
- `ADOPlayerController`：接收本地镜头输入，并把方向键平移和复位请求转发给 `ADOPlayerCameraManager`。
- `ADOPlayerCharacter`：只提供角色位置、朝向、速度和当前镜头目标点，不直接控制最终摄像机。

第一版也可以先用蓝图实现 `PlayerCameraManager` 或角色上的 Camera Component 验证手感，参数稳定后再将边界、目标点和反馈接口下沉到 C++。镜头不是服务器玩法逻辑，不需要为了联机同步而复制到 Character 或 PlayerState。

### 8.2 输入配置

镜头输入使用 Enhanced Input 的 Native Action，不走 GAS 技能输入流程：

```text
IA_CameraPan
  -> InputTag.Camera.Pan
  -> Axis2D
  -> 方向键上下左右

IA_CameraReset
  -> InputTag.Camera.Reset
  -> Started
  -> Home（推荐默认键）
```

在 `DA_InputConfig` 中完成 InputAction 到 GameplayTag 的映射，在 `IMC_Default` 中配置物理键。C++ 只绑定 GameplayTag，不直接依赖某个具体按键资源。

输入路由建议：

```text
Enhanced Input
  -> ADOPlayerController
  -> ADOPlayerCameraManager::AddCameraPanInput
  -> ADOPlayerCameraManager::ResetCamera
```

方向键输入只在本地生效，不需要经过 ASC，也不应该激活 GameplayAbility。角色的 WASD 移动继续由 `ADOPlayerCharacter::Input_Move` 处理，二者互不冲突。

### 8.3 鼠标常驻显示

游戏需要在战斗过程中始终显示鼠标时，PlayerController 使用 `GameAndUI` 输入模式，而不是 `UI Only`：

```cpp
bShowMouseCursor = true;

FInputModeGameAndUI InputMode;
InputMode.SetHideCursorDuringCapture(false);
InputMode.SetLockMouseToViewportBehavior(EMouseLockMode::DoNotLock);
SetInputMode(InputMode);
```

规则如下：

- 鼠标光标始终显示，用于点击 UI。
- WASD 继续控制角色移动。
- 方向键控制镜头平移。
- 鼠标移动不控制摄像机旋转。
- 不使用 `UI Only`，避免战斗中键盘输入被 UI 独占。
- UI 打开时可以通过更高优先级的 UI MappingContext 暂停角色和镜头输入。

如果暂时没有可交互 UI，也可以使用 `GameOnly + bShowMouseCursor = true` 做原型验证；正式版本需要同时支持游戏输入和鼠标点击时使用 `GameAndUI`。

### 8.4 不建议的实现方式

- 不要在 `Tick` 中直接把摄像机位置硬设置为角色位置，容易造成画面抖动。
- 不要让 Camera Component 读取控制器旋转来实现自由视角。
- 不要用 Camera Collision 自动解决横版房间边界。
- 不要在技能类中直接修改服务器角色的摄像机组件。
- 不要把摄像机位置写入 PlayerState 或作为网络属性复制。
- 不要用摄像机方向决定角色左右朝向；角色朝向应由 X 轴移动和技能规则决定。
- 不要让手动镜头偏移绕过玩家安全区和房间边界。
- 不要把鼠标光标显示简单等同于 `UI Only` 输入模式。

## 9. P0 实现顺序

### 阶段一：单角色镜头原型

1. 创建固定侧视透视摄像机。
2. 固定 Y 轴观察方向，关闭自由旋转。
3. 实现 X 轴死区和软跟随。
4. 实现 Z 轴跳跃跟随。
5. 增加方向键镜头平移和镜头最大偏移。
6. 增加玩家安全区，避免手动推镜头后玩家离开屏幕。
7. 增加 `Home` 镜头复位输入，并验证平滑回归。
8. 配置一个测试房间的镜头边界。
9. 配置鼠标常驻显示和 `GameAndUI` 输入模式。
10. 验证角色左右移动、跳跃、闪避和攻击时的画面稳定性。

### 阶段二：纵深和房间切换

1. 给测试房间增加 `DepthMin/DepthMax`。
2. 限制角色前后走位，摄像机保持侧视。
3. 增加前景遮挡、远近角色重叠和弹道命中测试。
4. 增加两个镜头边界体，验证房间切换过渡。

### 阶段三：战斗反馈

1. 接入普通攻击命中镜头反馈。
2. 接入受击、闪避和 Boss 阶段切换反馈。
3. 通过 GameplayCue 或本地消息总线接收表现事件。
4. 在 Listen Server + Client 下确认镜头反馈不影响权威战斗结果。

## 10. 验收标准

### 操作和构图

- 角色左右移动时，镜头不会跟随每个输入帧产生抖动。
- 角色在安全区内移动时，镜头基本保持稳定。
- 角色接近屏幕边缘时，镜头能平滑跟随。
- 跳跃、击飞和落地不会造成明显的镜头弹簧感。
- 角色沿 Y 轴前后移动时，画面不会左右漂移。
- 方向键可以在限制范围内移动镜头，松开后镜头保持当前位置。
- 方向键不能把玩家推到屏幕外。
- 按下复位键后，摄像机能在 0.15～0.25 秒内回到玩家构图中心。
- 鼠标始终可见时，WASD、方向键和 UI 点击仍能按预期工作。

### 战斗可读性

- 普攻、弹道、近战范围和敌人位置在不同纵深下仍能区分。
- 镜头反馈不会遮挡血条、技能栏和关键敌人信息。
- 大招镜头效果结束后能恢复正常战斗镜头。
- 角色翻面时，前视偏移不会瞬间跳变。

### 网络

- Listen Server + Client 下每个客户端可以独立跟随本地角色。
- 摄像机震动、FOV 和后处理不需要服务器复制。
- 服务器拒绝技能、延迟命中或角色受击时，不会留下永久镜头偏移。
- 摄像机系统不参与伤害、死亡、掉落和技能合法性判断。

## 11. 当前建议

当前最适合 DragonOath 的落地选择是：

```text
固定侧视透视摄像机
  + X/Z 软跟随
  + 方向键有限手动平移
  + 玩家安全区保护
  + Home 复位
  + 鼠标常驻显示的 GameAndUI 输入模式
  + Y 轴有限纵深通道
  + 每个房间独立镜头边界
  + PlayerCameraManager 统一管理
  + GameplayCue / 本地消息触发镜头反馈
```

先用一个矩形测试房间把“左右移动、前后走位、跳跃、普攻、闪避、怪物追击”全部跑通，再决定是否需要更强的俯角、动态缩放或大招专用镜头。镜头基础规则稳定后，后续新增职业和技能不应再修改摄像机核心结构。
