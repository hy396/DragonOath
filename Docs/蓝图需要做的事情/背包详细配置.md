# 背包系统详细蓝图配置手册

> 适用范围：在编辑器里补齐背包系统「蓝图资产层」的配置。
> 代码层（C++）已就绪，无需改 C++。本文档只讲**创建什么蓝图、继承什么类、放哪里、配什么**。
> 生成依据：2026-08-11 工作区源码事实（`Source/DragonOath/UI/Inventory`、`Source/DragonOath/ItemSystem`、`Source/DragonOath/Player/DOPlayerController.cpp`、Config/DefaultGame.ini）。

**结论**：你要做的不是「从零搭蓝图」，而是 (1) 确认并补完 `WBP_InventoryScreen`，(2) 创建物品 `DA_` 定义资产，(3) 在 PlayerController 上把界面类指到 `WBP_InventoryScreen`，(4) 配 GameplayTag。

## 1. 确认 / 补完 `WBP_InventoryScreen`（背包页面蓝图）

### 1.1 检查父类（必须先做）

1. 内容浏览器打开 `Content/BP/UI/WBP_InventoryScreen`
2. 蓝图编辑器左上角「类设置 / Class Settings」→ 看 **父类（Parent Class）**
3. 若父类是 `UDOInventoryScreen` → 跳到 1.3
4. 若父类是 `UserWidget` / `CommonActivatableWidget` 但不是 `DOInventoryScreen` → **需要新建正确父类**（见 1.2），旧资产可删

> 为什么必须是 `UDOInventoryScreen`：C++ 里 `PrimaryLayout->PushWidgetToLayerStack<UDOInventoryScreen>(...)` 强制按 `UDOInventoryScreen` 类型入栈；且 Screen 的 `RebuildWidget()` 已经用 Slate 把整个背包面板（`SDOInventoryEquipmentPanel`）建好了，**蓝图里不需要也不能再放子控件**。蓝图只作为「可配置外观外壳 + 焦点目标」。

### 1.2 若需重建（父类不对时）

1. 内容浏览器右键 → 蓝图类（Blueprint Class）
2. 父类搜索 `DOInventoryScreen`（全名 `UDOInventoryScreen`），选中
3. 命名 `WBP_InventoryScreen`，放到 `Content/BP/UI/`
4. 把旧的 `WBP_InventoryScreen` 重命名备份或删除后，用新资产占回该路径

### 1.3 在 `WBP_InventoryScreen` 里配置什么

`UDOInventoryScreen` 的 `RebuildWidget()` 是 **Slate 主导**（`SDOInventoryEquipmentPanel`），所以蓝图**设计器画布留空即可**。你要配置的是：

- **（可选）`WBP_InventoryScreen` 的「细节」面板**：无需改任何属性，C++ 已设 `SetIsFocusable(true)`、`GetDesiredInputConfig()` 返回 Menu 输入模式。
- **（推荐）绑定关闭逻辑**：C++ 已处理 `Esc` 关闭和 `OnCloseRequested`。若你想加一个「关闭按钮」，在蓝图 Graph 里调用父类 `DeactivateWidget`（或监听 ViewModel 的关闭请求）。当前 Slate 面板已自带关闭入口，无需额外做。
- **不要做的事**：**不要**在蓝图 Hierachy 里手动拖 `SDOInventoryEquipmentPanel` 或物品格——它们是 C++ Slate 创建的，蓝图拖了会重复/冲突。

> 验证页面能打开的最小步骤：按 `I` 或 `B`，应弹出背包面板（即使里面没物品也该显示空槽和装备槽位框）。

## 2. 在 PlayerController 上把界面类指向 WBP（关键一步）

`ADOPlayerController` 有个字段：

```cpp
UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "DO|UI", meta = (DisplayName = "背包界面类"))
TSubclassOf<UDOInventoryScreen> InventoryScreenClass;   // 默认 = UDOInventoryScreen::StaticClass()
```

默认是 C++ 类本身（也能跑，但用的是无蓝图的纯 Slate 外壳）。要让编辑器里你配置的 `WBP_InventoryScreen` 生效：

1. 内容浏览器找到 `BP_PlayerController`（或你的 PlayerController 蓝图子类；若直接用 `ADOPlayerController` 则需建一个蓝图子类 `BP_DOPlayerController`）
2. 打开其「类默认值 / Class Defaults」
3. 找到 **DO|UI → 背包界面类**
4. 选 `WBP_InventoryScreen`
5. 编译保存

> 若项目当前没有 PlayerController 蓝图，只有 C++ `ADOPlayerController`：按 `I`/`B` 依然能开（用默认 C++ 外壳），只是不走 `WBP_InventoryScreen`。要换皮肤再建蓝图子类不迟。

## 3. 创建物品定义资产（DA_ItemDefinition）

物品 = **DataAsset**，继承自 `UDOItemDefinition`。一个物品一个 `DA_` 资产，放在 AssetManager 已登记的扫描目录。

### 3.1 目录与命名

- 位置：`Content/DragonOath/Items/Definitions/`（对应 DefaultGame.ini 的 `Directories=((Path="/Game/DragonOath/Items/Definitions"))`）
- 命名：`DA_物品名`，例如 `DA_HP_Potion`、`DA_Iron_Sword`

> 若该目录不存在，先在内容浏览器建 `Content/DragonOath/Items/Definitions`。

### 3.2 创建步骤

1. 内容浏览器右键 → **杂项（Miscellaneous）** → **数据资产（Data Asset）**
2. 父类选 **`DOItemDefinition`**（搜索框输入 `DOItemDefinition`）
3. 命名 `DA_HP_Potion`，双击打开

### 3.3 `DA_HP_Potion` 要配的字段

打开后按分类填（都来自 `UDOItemDefinition` 的 `UPROPERTY`）：

**Item | Display（显示）**

- 物品名称：填 `生命药水`（FText）
- 物品描述：填 `立即恢复 50 点生命值`（多行）
- 物品图标：选一张 `TSoftObjectPtr<UTexture2D>` 图标（拖入 Texture2D）

**Item | Type（类型与稀有度，用 GameplayTag）**

- 物品类型 `ItemType`：在 `Item.Type.*` 下选，例如 `Item.Type.Consumable`（消耗品）/ `Item.Type.Equipment.Weapon` / `Item.Type.Material`
- 稀有度 `Rarity`：在 `Item.Rarity.*` 下选，例如 `Item.Rarity.Common`
- 物品标签 `ItemTags`：可加自定义标签（如 `Item.Consumable.RestoreHP`），用于 UI 筛选/逻辑判断

**Item | Rules（规则）**

- 最大堆叠数量 `MaxStackSize`：药水填 `99`，装备填 `1`
- 排序优先级 `SortPriority`：数字越小越靠前（如药水 `10`，武器 `5`）
- 出售价格 `SellPrice`：填 `5`

**Item | Fragments（物品配置片段，Instanced 子对象——这是物品「行为」的核心）**
点 `+` 添加片段，按物品种类选对应 Fragment 类：

- **消耗品** → 加 `DOItemFragment_Consumable`
  - 消耗品效果类型 `EffectKind`：选 `InstantRestore`（即时恢复）
  - 即时恢复数值 `InstantRestore`：按 `FDOResourceRestoreValues` 填（如 生命值 +50）
  - 公共冷却 `Cooldown`：按需填（同类型消耗品共享 CD）
- **装备** → 加 `DOItemFragment_Equipment`
  - 装备槽位 `EquipmentSlotTag`：在 `Equipment.Slot.*` 下选（如 `Equipment.Slot.Weapon.MainHand`）
  - 兼容槽位查询 `CompatibleSlotQuery`：一般留空（用精确匹配）
  - 需求等级 `RequiredLevel`：如 `1`
  - 职业需求查询 `RequiredProfessionQuery`：如 `Profession.Mage`（空=不限）
  - 装备技能集 `EquipmentAbilitySet`：可选，挂 `GA_` 技能集
  - 属性修正 `AttributeModifiers`：填 `FDOAttributeModifierValues`（攻击+10、防御+5 等），服务器自动转 SetByCaller 写 GAS
  - 最大耐久 `MaxDurability`：如 `100`，不需要填 `0`
  - （旧版 `BaseAttributeMagnitudes` 已弃用，别填）
  - 再加 `DOItemFragment_EquipmentAppearance`：填 `AppearanceId`（外观标识）、`VariantTag`、`Tint`（染色）
- **通用规则** → 加 `DOItemFragment_Inventory`
  - 可丢弃 `bCanDiscard`：true
  - 可出售 `bCanSell`：true
  - 唯一物品 `bUnique`：false
  - 拾取绑定 `bBindOnPickup`：false

> 一件装备通常同时有 `DOItemFragment_Inventory` + `DOItemFragment_Equipment` + `DOItemFragment_EquipmentAppearance` 三个片段；一件消耗品有 `DOItemFragment_Inventory` + `DOItemFragment_Consumable`。

### 3.4 多建几个样例物品

至少建 3~5 个用于联调：

- `DA_HP_Potion`（消耗品，即时恢复）
- `DA_MP_Potion`（消耗品，恢复法力）
- `DA_Iron_Sword`（装备，主手武器，+攻击）
- `DA_Leather_Armor`（装备，护甲槽，+防御）
- `DA_Iron_Ore`（材料，堆叠 99）

## 4. 配置 GameplayTag

背包系统重度依赖 GameplayTag，需在编辑器 **项目设置 → Gameplay Tags** 确认以下 Tag 存在（不存在则新增；建议也在 `DOGameplayTag.h` 里补 C++ 声明，保持单一来源）。

### 4.1 必须存在的 Tag

**物品类型 `Item.Type.*`**

- `Item.Type.Consumable`（消耗品）
- `Item.Type.Equipment.Weapon`（武器）
- `Item.Type.Equipment.Armor`（护甲）
- `Item.Type.Material`（材料）
- `Item.Type.Quest`（任务物品）

**稀有度 `Item.Rarity.*`**

- `Item.Rarity.Common` / `Item.Rarity.Uncommon` / `Item.Rarity.Rare` / `Item.Rarity.Epic` / `Item.Rarity.Legendary`

**装备槽位 `Equipment.Slot.*`**

- `Equipment.Slot.Weapon.MainHand` / `Equipment.Slot.Weapon.OffHand`
- `Equipment.Slot.Armor.Head` / `Equipment.Slot.Armor.Chest` / `Equipment.Slot.Armor.Legs` / `Equipment.Slot.Armor.Feet`
- `Equipment.Slot.Accessory.Ring` / `Equipment.Slot.Accessory.Neck`

**外观变体 `Equipment.Appearance.Variant.*`**（可选）

- 按需，如 `Equipment.Appearance.Variant.Default`

**UI 层 `Message.UI.Layer.Menu`**（已用于 `PushWidgetToLayerStack`）

- 确认 `DragonOathGameplayTags::Message::UI::Layer::Menu` 对应 Tag 存在，否则背包推不进 Menu 层

**UI 消息通道（ViewModel 监听，已硬编码）**

- `Message.UI.Inventory.Changed` / `Message.UI.Equipment.Changed` 等（见 `DOInventoryMessages.h`）；若 `DOGameplayTag` 里已声明就无需动

> 怎么确认：编辑器顶部菜单 **编辑 → 项目设置 → 游戏玩法 → Gameplay Tags → 添加新标签**，或用 **窗口 → 开发者工具 → Gameplay Tags** 浏览器搜索。

## 5. 让背包「有东西」可看（联调验证）

物品定义建好后，运行时才有数据。两种注入方式：

### 5.1 调试用（最快验证 UI）

`ADOPlayerController` 有 `DOAddInventoryItem(DefinitionName, Count)` 接口（C++ 已就绪）。可在蓝图/控制台调：

```
DOAddInventoryItem HP_Potion 10
DOAddInventoryItem Iron_Sword 1
```

（DefinitionName 对应 `DA_` 资产的 PrimaryAssetName，去掉 `DA_` 前缀，即 `HP_Potion`）

### 5.2 正式掉落（后续）

拾取物 `ADOItemPickup` + `TryAddItem` 已接好，做掉落物蓝图指向 `DA_` 定义即可。本文档先不展开。

## 7. 常见「没配置导致不显示」排查

| 现象                           | 原因                                                   | 修法                                                                                                 |
| ------------------------------ | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 按 I/B 没反应                  | PlayerController 未接管输入 / PrimaryGameLayout 未创建 | 确认用`ADOPlayerController`（或其蓝图子类），HUD 用了 `UCommonUISubsystem`/`PrimaryGameLayout` |
| 面板打开但是空白               | 没建/没加物品                                          | 用`DOAddInventoryItem` 注入，确认 `DA_` 在扫描目录                                               |
| 物品图标不显示                 | `DA_` 的 Icon 没填或路径失效                         | 回`DA_` 资产补 Texture2D                                                                           |
| 装备槽位不出现某件装备         | `EquipmentSlotTag` 不在 `Equipment.Slot.*` 里      | 在 GameplayTag 补对应槽位 Tag，并在`DA_` 里选对                                                    |
| 物品类型筛选无效               | `ItemType` Tag 没配                                  | 在`DA_` 的 `Item.Type.*` 选正确类型                                                              |
| 推送不到 Menu 层               | `Message.UI.Layer.Menu` Tag 不存在                   | 补该 Tag                                                                                             |
| 用了 WBP 但外观和 C++ 外壳一样 | `InventoryScreenClass` 仍指向 C++ 类                 | 回 PlayerController 类默认值，把「背包界面类」改成`WBP_InventoryScreen`                            |

## 附：关键 C++ 接口速查（仅供理解，不需改）

- 打开：`ADOPlayerController::ToggleInventoryScreen()` → `PushWidgetToLayerStack<UDOInventoryScreen>(Layer::Menu, InventoryScreenClass)`
- 物品加：`UDOInventoryComponent::TryAddItem(FPrimaryAssetId, Count)`（服务器）
- 物品用：`UDOInventoryComponent::TryUseItemByInstanceId(...)`（服务器执行效果）
- 物品定义解析：`UDOItemDefinitionSubsystem::ResolveItemDefinition(...)`（按 PrimaryAssetId）
- 物品定义类型：`UPrimaryDataAsset`，`PrimaryAssetType = "ItemDefinition"`，扫描目录已登记
- 页面类层级：`UDOInventoryScreen : UCommonActivatableWidget`（CommonUI 页面）
