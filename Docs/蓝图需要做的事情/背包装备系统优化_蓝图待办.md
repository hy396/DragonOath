# 背包装备系统优化：Phase 1 蓝图待办

本清单对应 `Item 系统 Phase 1：基础 Item 系统重构`。本阶段只迁移静态 ItemDefinition 数据、校验 Primary Asset 扫描和验证 UI/存档行为，不修改 FastArray 事务协议，也不引入装备 AbilitySet。

## 已由 C++ 完成

- `FDOItemInstanceRecord` 与 `FDOItemAffixRoll` 已迁移到 `ItemSystem/Core/DOItemInstanceTypes.h`，实例字段和词缀字段支持 SaveGame 序列化。
- `UDOItemDefinitionSubsystem` 已统一同步 Definition 解析，并提供 UI 异步加载入口。
- QuickBar 恢复允许合法消耗品在库存为 0 时保留 DefinitionId 绑定。
- `SortPriority` 已纳入库存排序。
- Tooltip、装备对比和自动化测试优先读取 `AttributeModifiers`，仅在类型化字段全零时兼容读取 `BaseAttributeMagnitudes`。

## 1. ItemDefinition 资产迁移

在内容浏览器打开 `/Game/DragonOath/Items/Definitions`，逐个打开继承 `DOItemDefinition` 的 DataAsset：

1. 装备资产在 `UDOItemFragment_Equipment > AttributeModifiers` 填写攻击、防御、生命、法力、暴击、命中、闪避、攻速、移速和吸血数值。
2. 不再向 `Equipment|Legacy > BaseAttributeMagnitudes` 写入新数据；旧 Map 仅作为迁移期间兼容读取。
3. 消耗品优先配置 `EffectKind`、`InstantRestore`、`TimedModifier`、`UseGameplayAbility` 或 `UseEventTag`；只有未迁移旧资产时才保留 `UseGameplayEffect`。
4. 为所有资产设置稳定且不重复的 `DisplayName`、`Icon`、`ItemType`、`Rarity`、`MaxStackSize`、`SortPriority` 和 `SellPrice`。
5. 保存资产后执行 Asset Actions > Validate，确认没有 Definition 校验错误。

## 2. Asset Manager 检查

打开 Project Settings > Asset Manager，确认 `ItemDefinition` 类型扫描到 `/Game/DragonOath/Items/Definitions`。如果项目使用自定义 Primary Asset Type，必须保证资产的 `GetPrimaryAssetId()` 与运行时保存的 `PrimaryAssetId` 类型一致。

## 3. GameplayTag 检查

确认以下现有 Tag 已注册，不要在蓝图中手写字符串创建同名 Tag：

- `Item.Type.Equipment`、`Item.Type.Consumable`、`Item.Type.Material`、`Item.Type.Quest`
- `Item.Rarity.*`
- `Equipment.Slot.*`
- `Data.Equipment.*`

新建 Tag 时先在 `DOGameplayTag.h/.cpp` 集中声明，再回到 DataAsset 选择该 Tag。

## 4. UI 验证

1. 启动 `UDOInventoryScreen` 对应的 CommonUI 页面，确认物品 Tooltip 能显示 `AttributeModifiers` 中的属性。
2. 将一个旧资产的数值从 Legacy Map 迁移到 Typed 字段，重新打开 Tooltip，确认显示结果不变。
3. 将消耗品数量用尽，确认 QuickBar 槽位仍显示该物品但不可用；再次添加同 Definition 的物品后，槽位恢复可用。
4. 使用不同 `SortPriority` 的物品执行整理，确认同一 ItemType 内优先级高的物品排在前面。

## 5. 存档验证

在 PIE Listen Server 中：

1. 添加带强化等级、耐久和词缀的实例物品。
2. 绑定一个消耗品并将其用尽。
3. 保存并重新加载，确认实例字段、词缀、库存槽位和零库存 QuickBar 绑定都保留。
4. 使用独立测试槽位，避免覆盖开发者本地正式存档。

## 6. 本阶段不需要创建的资产

- 不需要创建 `GE_DO_EquipmentAttributes` 蓝图；装备属性继续使用 C++ 原生 GE。
- 不需要创建装备主动技能、被动技能或 EquipmentInstance 蓝图；这些属于 Phase 3。
- 不需要为 ItemInstance 创建 UObject 蓝图；当前实例仍是 Owner-only FastArray 中的结构体记录。
