# 背包改造：蓝图与资产待办

本文记录背包、装备和物品快捷栏在 Unreal Editor 中仍需手动完成的配置。
背包主体已经由 `UDOInventoryScreen` 承载，并使用原生 Slate 创建布局、格子、拖拽、Tooltip、分页和装备槽；不要重新创建一个 Widget Blueprint 来替代 Slate 主体。

> 当前状态：C++ 原生 GE、动态 Spec 和 `Source/DragonOath/ItemSystem/` 目录重组已经完成。
> 旧字段 `BaseAttributeMagnitudes` 和 `UseGameplayEffect` 仍保留兼容入口，内容资产可以按本文逐项迁移，迁移完成前不要删除旧字段数据。

## 已由 C++ 完成

- `UDOInventoryComponent`：堆叠、容量、移动、交换、拆分、整理、删除、消耗和 Owner-only 复制。
- `UDOEquipmentComponent`：九个装备槽、穿戴/卸下事务、装备属性 GameplayEffect 和 Owner-only 复制。
- `UDOItemQuickBarComponent`：四格快捷栏、绑定消耗品、使用和 Owner-only 复制。
- `UDOInventoryScreen`：CommonUI 页面壳；页面内容由原生 Slate 构建。
- `SDOInventoryEquipmentPanel`：分类、分页、拖拽、双击、右键菜单、Tooltip、装备对比和装备槽拖放。
- `SDOItemQuickBarWidget`：底部居中的四格快捷栏 HUD。
- 自动化测试：背包核心算法、消耗品/快捷栏/存档、装备事务、装备存档往返、快照校验和战力公式测试已通过。
- 装备与外观已解耦：装备只负责装备槽、属性和 GAS；不配置装备 Mesh、武器 Actor 或外观同步。
- 源码已按物品领域统一归档到 `ItemSystem/Core`、`Inventory`、`Equipment`、`Usage`、`QuickBar`、`Pickup`、`AbilitySystem` 和 `Tests`。

## 1. 创建 ItemDefinition 测试资产

在内容浏览器中创建目录：

`/Game/DragonOath/Items/Definitions`

创建 8～12 个继承自 `DOItemDefinition` 的 DataAsset，命名建议：

- `DA_Item_HealthPotion_Small`
- `DA_Item_ManaPotion_Small`
- `DA_Item_Material_Iron`
- `DA_Item_Quest_Key`
- `DA_Item_Equipment_Head_01`
- `DA_Item_Equipment_Chest_01`
- `DA_Item_Equipment_Hands_01`
- `DA_Item_Equipment_Weapon_01`

每个资产至少配置：

- `DisplayName`、`Description`、`Icon`。
- `ItemType`：装备、消耗品、材料或任务物品。
- `Rarity`：品质标签。
- `MaxStackSize`：装备必须为 `1`，材料和消耗品按需要设置。
- `SortPriority` 与 `SellPrice`。
- `UDOItemFragment_Inventory`：确认是否可丢弃、可出售、唯一和拾取绑定。

装备资产额外添加 `UDOItemFragment_Equipment`：

- `EquipmentSlotTag`：使用 `Equipment.Slot.*`，不要创建部位枚举。
- `RequiredLevel` 与 `RequiredProfessionQuery`。
- `AttributeModifiers`：直接填写攻击力、防御力、最大生命、最大法力、暴击、命中、闪避、攻速和移速等数值。
- `MaxDurability`。

消耗品资产额外添加 `UDOItemFragment_Consumable`：

- 回复药水选择 `EffectKind = InstantRestore`，在 `InstantRestore` 中直接填写回复数值。
- 限时属性道具选择 `EffectKind = TimedAttributeModifier`，填写持续时间和 `Modifiers`。
- 需要动画、目标选择或多阶段流程时选择 `GameplayAbility` 并配置 `UseGameplayAbility`。
- 需要事件驱动时选择 `GameplayEvent` 并配置 `UseEventTag`。
- 同类物品需要共享冷却时，在 `Cooldown` 中同时填写 `CooldownTag` 和持续时间。
- 普通回复和限时 Buff 道具不配置 `UseGameplayEffect`，也不创建 GE 蓝图。

配置完成后执行内容浏览器的 Asset Audit / Data Validation，确认资产被扫描为 `ItemDefinition` Primary Asset。

## 2. 装备属性 GE 操作

改造完成后，`UDOEquipmentComponent` 默认直接使用 C++ 原生 `UDOEquipmentAttributeEffect`。普通项目配置不需要在 PlayerState 蓝图中指定装备 GE，也不需要创建以下蓝图资产：

`GE_DO_EquipmentAttributes`

如果迁移期间仍保留 `EquipmentAttributeEffect` 兼容字段，应保持默认的原生类；只有调试旧资产时才临时指定旧 GE 蓝图，完成迁移后删除该兼容入口。

所有装备共用原生 GE 类，但服务器会为每件装备创建独立 `FGameplayEffectSpec` 并保存独立 `FActiveGameplayEffectHandle`，因此卸下某个槽位时不会影响其他装备。

注意：装备属性必须进入 PlayerState ASC，不要在背包 Widget 中手动累加最终属性，也不要把装备字段写入角色外观。

## 3. 配置 PlayerState 蓝图默认值

打开玩家 PlayerState 蓝图的 Class Defaults，确认：

- `ProfessionAbilityConfig` 指向有效的职业技能配置。
- `DefaultProfessionTag` 使用已有的 `Profession.*` 标签。
- `InventorySaveSlotPrefix` 使用项目约定的槽位前缀。
- 原型阶段可保留 `bAutoLoadInventory = true`、`bAutoSaveInventory = true`。

背包、装备和快捷栏组件已经由 `ADOPlayerState` 创建，不要在蓝图中重复添加同名组件。

## 4. 配置并打开背包页面

`UDOInventoryScreen` 是 CommonUI 的原生壳。若项目已有 `PrimaryGameLayout` / UI Policy：

1. 如果尚未创建页面蓝图，在 `/Game/DragonOath/BP/UI` 新建 `WBP_InventoryScreen`，父类选择 `DOInventoryScreen`。
2. 打开 `/Game/BP/Player/BP_DOPlayerController` 的 Class Defaults，将“背包界面类”设置为 `/Game/DragonOath/BP/UI/WBP_InventoryScreen`。
3. 将 `UDOInventoryScreen` 的蓝图子类注册到菜单页面可创建的 Widget Class。
4. 将页面推入 `UI.Layer.Menu`。
5. 打开页面时确认本地玩家能获取自己的 `ADOPlayerState`。
6. 关闭页面时让 CommonUI 管理激活状态和输入焦点，不要在蓝图里创建独立窗口。

页面主体不使用 UMG Designer；Slate 会自行创建左右双栏、装备槽、分类选择器、分页、物品格和 Tooltip。

完整的从零创建、编译、绑定和 PIE 验证步骤见：
`Docs/蓝图需要做的事情/背包装备系统优化_Phase5_蓝图待办.md`。

## 5. 配置快捷栏 HUD

将 `SDOItemQuickBarWidget` 放入战斗 HUD 的原生 Slate 容器或现有 HUD 壳中，保持四个槽位底部居中布局。

需要在编辑器中确认：

- HUD 只在本地玩家创建。
- 快捷栏使用当前 PlayerState 的 `UDOItemQuickBarViewModel`。
- 绑定快捷栏时只传入物品 `PrimaryAssetId`，不要保存易失的 `InstanceId`。
- 快捷键请求最终调用 `UDOItemQuickBarComponent::RequestUseSlot`，不要在蓝图中直接扣数量或施加 GameplayEffect。

## 6. 消耗品效果配置

普通回复药水和限时 Buff 药水只创建 `DOItemDefinition` DataAsset，不创建以下 GE 蓝图：

- `GE_Item_HealthPotion_Small`
- `GE_Item_ManaPotion_Small`

只有存在动画、目标选择、持续施法、多段效果或异步确认时，才创建例如 `GA_Item_UsePotion` 的 GameplayAbility。Ability 负责复杂流程和表现，但最终仍通过背包组件的服务器接口提交物品消耗，不能直接修改背包数量。

编辑器填写示例：

1. 小型生命药水：`EffectKind = InstantRestore`，`InstantRestore.Healing = 100`。
2. 攻击药水：`EffectKind = TimedAttributeModifier`，`DurationSeconds = 30`，`Modifiers.AttackPower = 20`。
3. 同组药水公共冷却：`CooldownTag = Cooldown.Item.Potion`，`DurationSeconds = 2`。
4. 配置完成后运行 Data Validation，确认没有同时填写互斥效果字段。
